# Twitter Mutual Followers Integration

## Описание

Реализована функция для отображения взаимных подписчиков из Twitter, которые уже зарегистрированы в SolPoint.

## Архитектура

### База данных

1. **Таблица `twitter_connections`**
   - Хранит только взаимных подписчиков (mutuals)
   - Поля: `user_id`, `twitter_friend_id`, `twitter_friend_username`, `twitter_friend_avatar_url`, `synced_at`
   - Primary key: `(user_id, twitter_friend_id)`

2. **Поле `profiles.last_twitter_sync_at`**
   - Отслеживает время последней синхронизации
   - Используется для кэширования (синхронизация не чаще раза в 24 часа)

### API Endpoint

**GET `/api/twitter/mutual-followers`**

- Проверяет, когда была последняя синхронизация
- Если прошло меньше 24 часов - возвращает данные из БД
- Если больше - синхронизирует с Twitter API
- Использует пагинацию для получения всех подписчиков/подписок
- Находит пересечение по `twitter_id` (приоритет) или `username`
- Сохраняет только mutuals в таблицу `twitter_connections`
- Возвращает список пользователей, которые зарегистрированы в SolPoint

### Алгоритм синхронизации

1. Получаем всех подписчиков (followers) с пагинацией
2. Получаем все подписки (followings) с пагинацией
3. Находим пересечение по `twitter_id` (приоритет) или `username`
4. Сохраняем только mutuals в `twitter_connections`
5. Обновляем `last_twitter_sync_at` в `profiles`

### Поиск зарегистрированных пользователей

1. Ищем по `twitter_id` (для connections с числовым ID)
2. Ищем по `twitter_handle` (для connections с username)
3. Объединяем результаты, избегая дубликатов
4. Обновляем `subscription_tier` на основе активных подписок

## Миграции

Файл: `supabase/migrations/add_twitter_sync_fields.sql`

- Добавляет поле `last_twitter_sync_at` в таблицу `profiles`
- Создает таблицу `twitter_connections`
- Создает индексы для производительности

## Edge Cases

- **Username изменился** → `twitter_id` спасает (используется приоритетно)
- **Пользователь удалил аккаунт** → soft delete (не показывается в результатах)
- **Приватные аккаунты** → пропускаются (не возвращаются API)
- **Rate limit** → partial sync (используются кэшированные данные)
- **Ошибка синхронизации** → возвращаются кэшированные данные

## Производительность

- Синхронизация не чаще раза в 24 часа
- Данные кэшируются в БД
- Индексы на `user_id` и `twitter_friend_id` для быстрого поиска
- Пагинация для больших списков подписчиков
